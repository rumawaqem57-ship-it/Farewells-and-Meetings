# S2 交付层 · 导入说明（真酒馆）

> 目标：让聊天楼层的**显示层**变成《恋喰者》前端（iframe），但楼层原文与提示词保持不变。
> 这一关只能在真酒馆验；本地浏览器验不了 iframe 提升。

## 0. 前置条件

- SillyTavern 正在运行，**酒馆助手（TavernHelper / JS-Slash-Runner）已安装并启用**。
- 终端在 `F:\写卡\新\2` 下执行：

```bash
node serve.mjs
```

  保持这个窗口不要关。浏览器先直接打开 <http://localhost:5500/koi/index.html>，
  能看到「恋喰者」启动屏，说明服务正常。

> 如果这一步打不开：先解决服务，不要急着导正则。楼层变白屏，九成是服务没跑或端口不对。

## 1. 导入「开发正则」

1. SillyTavern → 扩展（Extensions）→ 正则（Regex）。
2. 点「导入」，选择本目录的 `koi-dev-regex.json`（或把内容整段粘贴进新建正则）。
3. 保存后，**勾选启用**。

字段含义（改之前先看）：

| 字段 | 值 | 为什么 |
|---|---|---|
| `scriptName` | `koi-界面-开发` | 带项目前缀，多个前端共存不打架 |
| `findRegex` | `/[\\s\\S]*/s` | 匹配整楼文本（含换行） |
| `replaceString` | `$('body').load('http://localhost:5500/koi/index.html')` 包在 `<body><script>` 里 | 酒馆助手把这个代码块提升为 iframe，再把我们的单文件整页灌进去 |
| `placement` | `[2]` | **只改显示层**（AI 输出），不改提示词；写错会污染变量解析 |
| `markdownOnly` | `true` | 只影响渲染 |
| `disabled` | `true` | 导入时先禁用，确认服务正常后再手动启用 |

## 2. 验收（S2 门）

打开任意一个已有 AI 楼层的聊天，看那一楼：

- [ ] 楼层显示层变成《恋喰者》启动屏（或至少是一个 iframe），不再是纯文本。
- [ ] 点「React 自检」按钮，计数会 +1（说明 iframe 里的 React 活着）。
- [ ] 楼层原文没变：点消息的「编辑」/「查看原始消息」，里面仍是 AI 写的文本。
- [ ] 提示词里没有 iframe 代码：查看提示词/变量解析正常（placement 必须是 `[2]`）。

> 本地验过的部分不算数：这一步只认真酒馆里看到的结果。

## 3. 排障

| 现象 | 先查 |
|---|---|
| 楼层空白/白屏 | `serve.mjs` 是否在跑；浏览器直开 URL 是否正常；F12 控制台第一行报错 |
| 楼层还是纯文本 | 酒馆助手是否启用；正则是否启用；`disabled` 是否忘了改 |
| 楼层显示一段代码文本 | 酒馆助手没把代码块提升成 iframe（扩展未启用/版本不支持） |
| 提示词里出现 iframe 代码 | `placement` 被写成 `[1]` 或含 1；改回 `[2]` |
| 改了代码但页面不变 | 浏览器强刷（Ctrl+F5）；确认 `npm run build` 成功且 `dist/koi/index.html` 时间戳更新 |

## 4. 正式版（等 CDN 发布后再用）

`koi-official-regex.json` 是正式版模板：

- 把 `<你的GitHub用户名>/<仓库名>` 换成真实仓库；
- **正式 JSON 里绝不允许出现 localhost**；
- 正式版 `disabled: true` 导入，发布完成后再启用；
- 发布铁律：先 `npm run build` **完全结束**，再单独发布；发布后核对 CDN 字节数 == 本地 `dist/koi/index.html` 大小。
