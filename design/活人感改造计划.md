# 《恋喰者》活人感改造计划（对照 BV1gant6mETF 拆解）

> 依据：视频逐帧拆解（`design/活人感对话交互_拆解.html`）+ 当前 `src/koi` 源码 + `恋喰少女_世界书.json`（16 条）。
> 前置教训：**S21 已回滚过一轮"对话节奏"改造**（标点停顿 / 换句进场 / 呼吸 / AUTO 抖动），本计划不再碰打字机节奏与翻页节奏。

## 一、视频七手法的取舍

| 视频手法 | 对你这张卡 | 结论 |
|---|---|---|
| ① 关键词输入框（体感自由、实现受限） | 你已是自由输入 + `<options>` 双通道 | **已有，不重做**；只加"关键词胶囊"降低空输入门槛（P4） |
| ② 台词接住玩家语法（"宾语呢？"） | 零前端成本，纯世界书 | **做（P2，最高性价比）** |
| ③ 眼镜反光＝情绪遮罩 | 恋喰有更好的等价物：舌套 / 舌尖 / 抑制药起效 | **做（P1），但改成一次性事件演出，不做常驻动画** |
| ④ 数值飘字与表情同帧 | `affection` 世界书已在用，前端零感知；档案 `favor` 是写死的假数据 | **做（P0），本计划核心** |
| ⑤ 台词说不完整（省略号收尾） | 这是节奏域，S21 刚回滚 | **不做**，只在世界书写"句子别超 20 字"（并入 P2） |
| ⑥ 立绘可点击查部位 | 已有 6 张 520×760 表情立绘 | **做（P3），热区限制在 3 处** |
| ⑦ 角色有自己的日程（DAY/体能/果实） | D6 已定"多角色位置不做"，但有天气昼夜 | **轻量借用（P3 附带）**：档案里显示她的"此刻状态"而非作息系统 |

**明确不做**：战斗系统、部位黏度系统（调性不匹配，且世界书无此设定）、角色地点池、小手机。

## 三、计划（P0 → P4）

### P0 · 探针：先确认 `affection` 到底存不存在
- **为什么排第一**：世界书条目 1 用 `<%_ vars.affection %>` 判三阶段，但 16 条里没有 `[initvar]`／`[mvu_update]`，说明这个变量的来源在前端之外（Izumi 预设的 MVU，或根本没落盘 → 三阶段永远走"初始狩猎"分支）。
- **做什么**：在 `Playback` 挂载时读一次并打印：`getTavernGlobal('Mvu')` → `Mvu.getMvuData({type:'message'|'chat'})` → `getVariables({type:'chat'}).stat_data` → `getVariables({type:'chat'})` 四层，全部 try/catch。
- **产出**：一份真机 console 记录，确定「有 / 无 / 叫什么名字」。
- **分支**：
  - 有 → P1 直接接。
  - 无 → 二选一：①补 `[initvar]` + `[mvu_update]` 两条世界书（改动协议，需重验 AI 输出）；②降级为「让 AI 在 `<content>` 外用一行 `［好感度+3］` 控制行」，前端解析后即时飘字（改前端协议，不动 MVU）。**推荐 ②**：不碰 MVU 契约，改动面最小。
- **验收**：真酒馆 console 里能看到确定的数值来源；拿不到时不崩只是不显示。

### P1 · 数值可见化：HUD + 飘字 + 表情同帧（本计划主体）
- **为什么对恋喰有用**：你的核心张力是「她越喜欢你 = 她越危险」。这个张力现在完全藏在 AI 的脑内，玩家看不见。把它做成一条会涨的细条 + 变化时飘字，等于把世界观变成可感知的压力。
- **做什么**：
  1. `playback/HudBond.tsx`：一条细横条（不用大数字），文案随区间变（<40 饥饿狩猎 / 40–75 食色混淆 / ≥75 真心恐惧，直接用世界书三个阶段名），不新增变量。
  2. `components/FloatingDelta.tsx`：`+3` / `-1` 飘字，红色=涨、青灰=跌，1.6s 淡出，`pointer-events:none`。
  3. 同帧触发：数值变化与表情切换在同一个 `setState` 批次里，禁止先切表情后补数字。
  4. `CharacterArchive` 的 `favor` 改读真实值，读不到回退现有静态值（降级不崩）。
- **改动面**：新建 2 个组件 + `Playback.tsx` 挂载 + `archiveData.ts` 数据源旁路。
- **风险**：数值一旦可见，玩家会开始"刷数值"——建议 HUD 只显示区间名与条，**不显示精确数字**（飘字除外）。
- **验收**：本地假数据可播；真机一轮对话后条与飘字对齐 AI 输出，且不影响打字机（Profiler 无父级重渲染）。

### P2 · 世界书加「接住语法」与「短句」两条（零前端）
- **为什么值得**：视频里最像活人的一句全是提示词产物，前端一分钱不用花。
- **做什么**：世界书「输出格式规范」追加两条约束：
  - 玩家输入 ≤8 字或语义含糊（只有"喜欢你""嗯""随便"这类）时，角色先用半句复述玩家的原话，再针对**表达方式**而不是内容回应（例：`"……你说喜欢，喜欢什么？宾语呢。"`）。
  - 单句台词不超过 20 字，允许以省略号开头，禁止排比与工整对仗。
- **风险**：Izumi 预设可能覆盖格式条目；需确认条目插入深度（蓝灯常驻 vs 关键词触发）。改完备份世界书（沿用 `.backup-<日期>.json` 惯例）。
- **验收**：真机连发三句超短输入，三句都能被"接住"；正文里不出现格式破坏（`<content>` / 说话人标签仍正确）。

### P3 · 一次性演出：遮罩 + 点击立绘
- **遮罩**（对应视频的眼镜反光）：恋喰版三个候选——舌套松动（下半脸暗一瞬）、抑制药起效（画面轻微去饱和 200ms）、理智临界（立绘边缘泛红）。**做成事件触发的一次性演出**（由剧本控制行触发），不做常驻动画，避免重蹈 S21。
- **点击立绘**：`CharacterStage` 加 3 个百分比热区（头 / 手 / 腹），点中后底部浮一条 2 秒小字，不进对话流、不暂停打字。
- **为什么限制 3 处**：热区越多，文案维护成本指数上升，且容易点穿对话框。
- **验收**：点三次不同热区都有正确文案；点空白不响应；与翻页点击不冲突（事件冒泡必须停）。

### P4 · 关键词胶囊（可选，最后做）
- 输入框上方 3 个胶囊（如「撒娇」「试探」「冷淡」），点了**填入输入框**而不是直发（保持"起草"纪律）。
- 价值主要是降低空输入的心理门槛，属于锦上添花。

## 四、建议执行顺序

```
P0 探针  ──→   P1 数值可见化  ──→  P2 世界书两条  ──→  P3 遮罩/点击  ──→  P4 胶囊
（必须）        （核心收益）          （零成本高感）      （需素材）
```

P1 与 P2 可以并行：一个动前端，一个动世界书，互不阻塞。

## 五、三条不做的事（避免重复劳动）

1. **不再调对话节奏**（S21 已回滚，`_evidence/rhythm-check.mjs` 留档）。
2. **不引入"立绘部位黏度"**——那是视频作者自己的题材红利，恋喰的张力在"吃与被吃"，不在"摸哪里"。
3. **不为"活人感"新增一套立绘**——6 张差分够用，缺的是演出层不是素材层。
